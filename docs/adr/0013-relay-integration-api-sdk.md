# ADR-0013 PII Relay 연동 방식: HTTP API + 얇은 Python SDK

- 상태: 채택 (2026-11-11)
- 표기: "기본값을 명시하고 빌더 재량으로 둔다"는 **[사용자 결정]**, 기본값(HTTP API + SDK)은 **[Claude 제안]** / 공통 기준은 설계 문서 §24.1

## 결정
기본 연동은 앱이 Relay의 **HTTP API**(tokenize, index, mask, tickets 등)를 **얇은 Python SDK**로 호출하는 방식이다. **투명 리버스 프록시**는 선택 확장으로 두고, **사이드카**는 채택하지 않는다.

## 맥락
- 핵심 산출물은 "두 번째 앱(MiniShop)을 설정과 SDK 호출만으로 연동"이다. 연동 방식이 단순해야 1인 범위 안에서 두 앱 모두를 끝낼 수 있다.
- 안티목표: Relay를 범용 제품처럼 과하게 일반화하는 것.

## 비교 후보
HTTP API + SDK, 투명 리버스 프록시(VGS Inbound Relay 방식), 사이드카(앱 Pod 안 Relay 에이전트)

## 비교표
| 후보 | C2 (25%) | C3 (25%) | C4 (20%) | C5 (10%) | C6 (10%) | C7 (10%) | 가중 합 |
|---|---|---|---|---|---|---|---|
| **HTTP API + SDK** | 5 | 3 | 5 | 5 | 4 | 5 | **4.40** |
| 투명 리버스 프록시 | 4 | 5 | 2 | 5 | 3 | 3 | 3.75 |
| 사이드카 | 3 | 3 | 3 | 5 | 3 | 4 | 3.30 |

| 관점 | HTTP API + SDK | 투명 프록시 | 사이드카 |
|---|---|---|---|
| 앱 메모리의 평문 | 처리 중 잠시 존재 | 없음 | 앱 메모리에 잠시 존재 (사이드카로 보내기 전) |
| 앱 코드 변경 | SDK 호출 몇 줄 | 거의 없음 | SDK 대신 localhost 호출 |
| 구현 난도 | 낮음 | 높음 (JSON/form/multipart 파싱, 스트리밍, 오류 매핑) | 중간 (주입, 수명 주기) |
| 장애 범위 | PII 관련 기능만 실패 | Relay 장애 = 앱 전체 중단 | 앱 Pod마다 사이드카 장애 지점 |
| 자원 | Relay 한 곳 | Relay 한 곳 (모든 트래픽 경유) | 앱 Pod마다 추가 메모리 |
| 디버깅 | 쉬움 | 어려움 (앱이 보는 요청 ≠ 사용자가 보낸 요청) | 중간 |
| 보안상 이점 | 기본 | 앱 침해 시에도 PII 원문 없음 | 앱과 같은 Pod라 보안 경계가 약함 (같은 네트워크 네임스페이스) |

## 왜 이것인가
1. 1인 범위 안에서 **두 앱 연동까지 끝낼 수 있는** 유일한 방식이다. 핵심 산출물을 우선한다.
2. 연동 diff가 "설정 파일 + SDK 호출 몇 곳"으로 작고 읽기 쉬워, 재사용성 증명(S10)에 가장 잘 맞는다.
3. 사이드카는 Pod 단위로 메모리가 늘고, 같은 Pod 안이라 보안 경계로서 이점이 거의 없다. 프록시 방식의 보안 이점은 크지만 구현 비용이 크다.

## 포기한 것 (트레이드오프)
- 앱이 가입·주문을 처리하는 순간에는 평문을 메모리에 잠깐 갖는다. 앱이 침해되면 **그 순간 입력되는 PII**는 노출될 수 있다 (저장된 PII는 아님). §22 정직한 한계에 적는다.
- 앱 개발자가 SDK를 "올바르게" 불러야 한다. 잘못 쓰면(예: 평문을 앱 DB에 그대로 저장) Relay가 막을 수 없다 → CI 카나리 검사와 `check_no_crypto.sh`(허용 목록 밖의 PII 암호화·키 접근·PII 필드 HMAC 탐지)로 일부 탐지.

## 결정을 바꾸게 될 조건
- M6까지 끝나고 시간이 남으면: MiniShop 가입 폼 한 개에만 투명 프록시를 적용해 "같은 설정 파일로 두 방식 모두 가능"을 보여준다.
- 앱 메모리의 평문까지 없애는 것이 요구가 되면(예: PCI DSS 범위 축소): 투명 프록시를 기본으로.

## 면접용 한 줄 답변
"혼자서 두 앱 연동까지 끝내는 게 목표라 가장 단순한 HTTP API와 얇은 SDK를 기본으로 했습니다. VGS 같은 투명 프록시 방식이 앱 메모리에서도 평문을 없애 더 안전하다는 건 알고 있어서, 그 차이를 한계로 문서에 적고 선택 확장으로 남겼습니다."
